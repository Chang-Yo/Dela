# Dela

以 Project 为中心，连接交大校园信息和本地文件，提供轻量编辑与 Agent 协作的桌面工作台。

当前包含真实资料与项目工作区、邮箱客户端和个人课表同步。应用界面品牌与桌面应用图标统一使用 `assets/Dela_white_bg.svg`（原生窗口/安装包使用同设计的 PNG 伴生文件）。左侧导航为首页、项目、资料、邮箱、课表（设置在侧边栏底部）。邮箱通过 IMAP（mail.sjtu.edu.cn:993）同步文件夹与邮件；凭据经 Electron `safeStorage` 加密保存在本机，邮件缓存于本地 SQLite。课表通过独立的 jAccount 登录窗口访问教学信息服务网，按学期缓存课程、教师、教室、校区、节次、教学周和可取得的学期日期；提供带时间轴的周视图、月视图、窄屏日程列表，开学日期可在应用内手动设置与修改，月视图支持拖拽跨天创建保存在本地 SQLite 的个人任务，任务可从八色低饱和候选色中选配色（课程按课程号自动分配同一套色）。资料页已接入 Canvas 学期、课程、目录、模块和作业；项目支持持久化文件夹、资料引用、Markdown 笔记、分屏阅读和正文问答。窗口使用自定义标题栏，窗口操作经 preload 受控 IPC 执行；标题栏左侧依次为侧栏开关、后退/前进（按视图导航历史，与邮箱离开确认共用守卫）和帮助入口（链接后续接入）。主侧栏在宽屏经标题栏按钮完全折叠，窄屏改为左上角菜单按钮控制的覆盖式两级抽屉——邮箱视图首击直达邮箱功能层（文件夹、发送邮件、账号、退出登录），抽屉顶部「主菜单」返回导航层；邮箱、项目、资料页内的面板共用 48px 图标折叠栏、1px 拖拽拉伸线和 h-11 工具栏。

邮箱同步已用真实账号验证：文件夹列表、信头、摘要与正文（含纯 HTML 邮件）均正确拉取并缓存。发送邮件已支持加粗、斜体、HTTP(S) 超链接、正文图片和附件，并由用户在正常应用会话中完成手动发送；草稿只保留在当前编辑界面，离开前会提示抛弃。收到的附件可点击并在每次下载时显示系统保存位置对话框；后台定时轮询与多账号尚未实现。

课表的数据结构与会话接口已根据教学信息服务网现行实现及公开客户端交叉核对，周/月视图和本地事件已用脱敏数据完成宽、窄窗口渲染检查；本人账号的 jAccount 登录、真实课表返回以及响应中学期日期的实际格式仍待应用内实测，因此暂不将远端同步和真实日期映射标记为已验证完成。旧缓存没有学期日期时，可在页头或月历提示条中手动设置开学日期，课程照常按教学周显示；下次成功同步取得权威日期后会覆盖手动值。官方开放平台也提供 Education API，但需要本项目无法取得的应用 `client_id`，不作为实现路线。

基础工程已通过类型检查、格式检查、开发与生产启动以及 Windows 可执行目录的冒烟验证；尚未验证 NSIS 安装流程和其他平台。

## 开发基线

- 本地单用户，桌面优先；Electron 跨平台实现，Windows 首先验收。
- Electron 44.3.0、React 19.2.8、TypeScript 7.0.2、Vite 8.2.2、pnpm 12.3.4。
- 单仓库、单 package，不使用 monorepo；`pnpm-workspace.yaml` 仅保存 pnpm 12 项目设置，无子包。直接 Vite 构建，electron-builder 打包。
- 项目关联校园资料和本地目录；轻量 Markdown 编辑，复杂工程用 VS Code 等专业软件打开。

## 本地开发

邮箱按连接表单、文件夹栏、邮件列表、阅读面板、写邮件面板与 HTML 正文拆分组件，格式化和 HTML 文档处理各有独立 TS 文件。邮件优先读取 HTML，保留内联样式、样式表和表格，支持 CID 图片、适应宽度/原始布局、纯文本切换、远程图片开关和经系统浏览器打开的正文链接。文件夹栏记忆折叠状态，图标位置保持稳定；打开未读邮件后会同步更新列表与文件夹未读数，窄屏经两级抽屉访问文件夹与账号操作。

其余功能页沿用邮箱页的交互语言：拉伸线（`components/ui/resizer.tsx`，含 aria 值、方向键步进与外扩命中区）、折叠按钮（`panel-toggle.tsx`）与浏览器预览提示（`desktop-only-notice.tsx`）为共享组件。资料和项目共用树状目录、文档标签与阅读/编辑区，目录保留折叠入口，助手从文档工具栏打开；课表拆分为视图、周/月历、事件弹窗与格式化工具，工具栏对齐邮箱风格；设置页为分区导航加右侧详情（数据与服务/外观/关于）：可直接配置或断开 Canvas、配置致远一号模型和 API Key、选择工作目录；邮箱与课表使用清晰的「前往」入口进入各自完整配置页。主题选择经受控 IPC 保存，立即同步 Electron 原生主题与页面 token。侧栏与各面板的折叠状态保存在 localStorage。

邮件 HTML 仍在无脚本、不同源的 sandbox iframe 内显示；远程图片沿用默认显示，可在单封邮件内关闭。外部样式表、字体、脚本和表单提交不加载；Outlook 专有 VML、不受支持或超出 2 MB 图片总预算的 CID 图片不能保证还原。旧缓存打开时尝试重新读取，失败则保留离线正文。数据库 v2 迁移前保留本地备份。附件按 MIME part 流式下载到用户每次选择的位置；旧缓存中没有 MIME part 的附件需重新同步后才可下载。

构建后可运行 `pnpm exec electron scripts/mail-smoke.cjs`，使用独立测试目录和脱敏数据检查 HTML 隔离、侧栏折叠、写邮件交互、未读数更新、请求竞态及窄屏布局；截图保存到被忽略的 `.tools/`。`pnpm test` 包含 MIME 正文选择与 CID 图片测试。本次自动化没有再次发送真实邮件。

安装 Node.js **24.21.0** 和 pnpm **12.3.4**。本机已将两者安装在被忽略的 `.tools/` 中，不改变全局环境；在 PowerShell 中先启用：

```powershell
. ./scripts/use-local-tools.ps1
node --version
pnpm --version
```

新克隆仓库不包含 `.tools/`，需自行安装上述版本；也可将官方 Windows Node ZIP 解压到 `.tools/node-v24.21.0-win-x64`，再使用该 Node 的 npm 执行 `npm install --prefix .tools/package-manager pnpm@12.3.4`。

```sh
pnpm install
pnpm dev
```

安装会通过 Electron 提供的 `install-electron` 命令下载运行时。pnpm 仅允许明确的依赖脚本；better-sqlite3 13 使用随包提供的预编译模块，当前关闭源码重建。新增原生依赖时重新评估此设置。

| 命令                                | 用途                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| `pnpm dev`                          | 启动开发服务器和窗口，监听主进程/preload 变更                      |
| `pnpm build`                        | 类型检查与三个入口的生产构建                                       |
| `pnpm start`                        | 启动已构建产物                                                     |
| `pnpm format` / `pnpm format:check` | 格式化 / 检查格式                                                  |
| `pnpm test`                         | Vitest；包含 MIME 正文选择、CID 图片与失败回退测试                 |
| `pnpm smoke`                        | 构建后验证 Electron 内 SQLite、React 渲染和 preload 隔离，自动退出 |
| `pnpm package:dir`                  | 生成未安装的可执行目录                                             |
| `pnpm package:dist`                 | 生成当前平台安装包                                                 |

Windows 打包目录可运行 `dist/win-unpacked/Dela.exe --smoke-test` 做相同检查。当前没有命令行凭据导入功能，启动不会读取仓库 `.env`；邮箱账号只能在应用内配置。

打包入口限定为 `out/` 和包元数据（构建器另收集生产依赖）。`knowledge/` 默认忽略，仅公开接口索引进入 Git；仓库文档、个人凭据与 `.tools/` 均不属于安装资源。

## 自动发布安装包

### PR 与 main 检查

`.github/workflows/check.yaml` 在 PR 创建、更新、重新打开及 push 到 `main` 时运行。Windows x64、macOS x64/arm64、Ubuntu x64 使用与发布一致的 runner 和固定 Node/pnpm 版本，分别执行冻结锁文件安装、`pnpm build`（含类型检查）、`pnpm test`、`pnpm smoke`、应用目录打包及打包后冒烟。`pnpm format:check` 仅在 Ubuntu 任务执行一次。检查不生成安装包或发布 Release，仅使用 `contents: read`；同一 PR 或 main 分支的新提交取消旧检查。

若要限制合并，在 GitHub 的 main 分支规则中将 `Check win-x64`、`Check mac-x64`、`Check mac-arm64`、`Check linux-x64` 四项设为必需检查；仅添加 workflow 不会自动启用分支保护。

### 升版与发布

使用以下命令修改 `package.json` 的应用版本，npm 负责 SemVer 校验与递增：

| 命令                                        | 示例（从 `0.1.0` 开始） |
| ------------------------------------------- | ----------------------- |
| `pnpm version:patch`                        | `0.1.1`                 |
| `pnpm version:minor`                        | `0.2.0`                 |
| `pnpm version:major`                        | `1.0.0`                 |
| `pnpm version:bump 0.2.0-beta.1`            | 指定预发布版本          |
| `pnpm version:bump prerelease --preid beta` | `0.1.1-beta.0`          |

命令不自动创建 Git commit/tag，也不推送或发布。当前单包 pnpm 锁文件不记录应用自身版本，升版无需修改锁文件。preload 在构建时从 `package.json` 内联版本，设置页与冒烟检查随之同步；升版后重新构建，开发模式需重启。检查完成后自行提交并推送对应 tag。

`.github/workflows/release.yml` 在推送 `v*` tag 时构建并发布 GitHub Release；tag 必须等于 `v` 加 `package.json` 的版本，例如 `v0.1.0`。先提交版本和代码，再执行 `git tag v0.1.0`、`git push origin v0.1.0`。含预发布后缀的版本（例如 `0.2.0-beta.1`）会发布为 prerelease。

工作流合入默认分支后，也可在 Actions → Release installers → Run workflow 中填写已有 tag。手动运行构建该 tag 指向的代码，使用相同版本校验和发布流程。已存在的 Release 不自动覆盖；发布失败若留下草稿，检查并删除该草稿后可重跑同一 tag。

| 平台    | 最低系统基线     | 架构                 | 产物               | GitHub runner                |
| ------- | ---------------- | -------------------- | ------------------ | ---------------------------- |
| Windows | Windows 10       | x64                  | NSIS `.exe` 安装包 | `windows-2022`               |
| macOS   | macOS 13 Ventura | x64、arm64，分别构建 | `.dmg`             | `macos-15-intel`、`macos-15` |
| Ubuntu  | Ubuntu 24.04 LTS | x64                  | `.AppImage`        | `ubuntu-24.04`               |

以上是项目选择的运行基线，不代表最低系统实机兼容性已验收；[Electron 44 要求 macOS 13 或以上](https://www.electronjs.org/blog/electron-44-0)，该下限也写入打包配置。Ubuntu AppImage 需 `libfuse2t64`，下载后赋予执行权限即可运行。GitHub runner 是构建环境，与最低运行系统不同。

四个构建任务均执行锁文件安装、类型检查与生产构建、单元测试、Electron 冒烟及打包目录启动检查，全部成功才统一创建草稿 Release、上传安装包并公开。Linux 冒烟通过 Xvfb 运行，并仅在临时 runner 中放开 AppArmor 对用户命名空间的限制以运行 Electron sandbox。安装包名包含版本、系统和架构，避免产物重名。仅发布任务具有 `contents: write`，使用内置 `GITHUB_TOKEN`，无需另配发布 token。

当前未配置 Windows 签名、Apple Developer ID 签名或公证，安装时可能遇到 SmartScreen/Gatekeeper 提示。工作流中的冒烟检查验证打包后程序及 SQLite/preload，不代替 NSIS 安装过程或 DMG/AppImage 最低系统实机验收；跨平台流水线结果需在 GitHub 首次运行后确认。

## 资料与项目工作区（2026-09-12）

- 资料侧栏依次展示“Canvas 资料”“我的内容”“归档”三个目录；归档默认收起。Canvas 资料默认只展示最新学期和“未标注学期”；其他已同步学期显示在归档。用户内容的“归档”操作会将条目及其子项移入同一归档目录。可切换为按来源浏览。Canvas 文件按 `parent_folder_id` / `folder_id` 还原目录，课程模块保留为独立目录轴，模块与文件树引用同一个来源 ID。作业显示完整 HTML 要求、截止时间和可取得的本人提交附件。
- 在资料页连接个人 Canvas Access Token，刷新课程列表；展开尚未同步的课程时按需读取，之后可单独刷新课程。同步只读取课程、目录、文件和模块等清单元数据，文件本体在首次打开或下载时才下载并缓存；作业/讨论列表响应中已提供的正文会随课程同步保存。所有列表跟随 Link 分页，单个栏目失败保留旧缓存并显示具体错误。筛选只检索已同步的名称，不声称搜索未读取的课程全文。
- “我的内容”支持新建文件夹、嵌套、重命名、移动、移除与关联本地文件；文件夹可以直接“作为项目开展”，原结构与资料引用保留。源资料可加入多个文件夹或项目，不复制原件。移除文件夹或项目只删除应用内记录，不删除 Canvas 或磁盘原件。
- 资料和项目共用 Explorer 与文档工作区。标签页、当前文档、目录展开状态、文本/HTML 阅读位置保存到 SQLite；仅在当前有打开文档时显示标签栏，文件夹或项目选中后不在右侧渲染详情，也不展示先前的文件标签。文档顶部为可点击的面包屑（所属项目 › 目录 › Canvas 课程与目录链、截止时间），替代重复的文件名行，点击面包屑在目录中定位；文档工具栏按文件类型显示——笔记为预览/编辑切换、保存（干净时置灰）、在文件夹中显示与重新载入，Canvas 资料为加入文件夹、下载（文件类）、打开原文与重新载入。目录使用 Mail 的 h-11 工具栏、48px 折叠入口、可拖动分隔线与固定内容宽度的裁剪过渡；窄屏以覆盖式目录访问内容。树支持方向键、Enter、Home/End 和项目内容操作菜单。参照 VSCode 文件资源管理器：目录头部为带悬浮提示的纯图标按钮组（新建笔记/新建文件夹/关联本地文件/全部收起）；“我的内容”树支持拖拽移动——拖到文件夹或项目上放入（放置目标高亮，成功后自动展开，自身子树不可作为目标），拖到目录空白处移到顶层，主进程继续做循环校验；双击目录空白处直接新建笔记。触屏与窄屏仍经条目操作菜单完成同样操作。
- 直接阅读 PDF、图片、HTML 与文本，支持固定文档并排阅读、选取 HTML/文本段落记入笔记。PDF 通过应用受控的 `dela-resource` 地址按 Range 从磁盘缓存流式读取，不把整份文件经 IPC、Zustand 和 Blob 复制到 renderer；关闭非编辑文档标签会释放内容缓存，固定文档与当前文档相同时不重复创建阅读器。Markdown 笔记使用 CodeMirror 编辑器，提供行号、语法高亮（GitHub Light/Dark 配色，跟随系统明暗）、列表/引用续写与撤销历史；编辑、预览、自动保存和 Ctrl/Cmd+S 保留，预览中代码块同样按语言高亮。有未保存修改时退出会提示。笔记是磁盘 `.md` 文件，默认按“文档/Dela/工作区/项目/子文件夹/笔记名.md”保存；文件夹与项目对应真实目录，重命名和移动同步磁盘及数据库路径。同名文件自动加序号，非法文件名字符会替换。设置中的保存位置影响新建顶层内容与新下载课程资料；已有项目中的新笔记继续保存在该项目目录。保存前对照内容摘要，发现外部修改会保留草稿并提示重新载入或另存为新笔记。
- 助手支持致远一号的正文问答，按项目或资料工作区保存对话。发送前手动勾选本次引用的已打开正文；只有选中正文、用户问题和最近 12 条对话送往模型。回答可保存为笔记；助手没有执行命令、修改现有文件或提交作业的工具。PDF 全文解析、流式回复、取消模型请求和多会话切换尚未实现；PDF 可在阅读器查看，问答时可自行粘贴所需文字。
- Canvas 下载经过主进程与缓存，响应正文流式写入临时文件，大小校验通过后才原子登记为缓存；跳转到对象存储时不转发 Authorization，凭据、下载签名链接和本地文件路径均不传入 renderer。HTML 移除活动内容并置于禁止脚本的 sandbox iframe 中；允许同源访问仅用于应用捕获选区和接管链接，iframe 无 preload API。网页脚本不能调用新增 IPC，主进程校验主 frame 与参数。

磁盘存储：Canvas 文件按“Dela/课程资料/学期/课程名 [课程 ID]/来源目录/文件名”保存，模块和项目引用共享同一来源版本，不为每个项目复制文件。来源更新保留之前的文件，新版本遇到重名加序号。旧 UUID 笔记在加载工作区时复制迁移，迁移前备份数据库为 userData 下的 `dela-before-storage-tree.db`；旧哈希缓存在加载资料列表或读取文件时复用迁移，不重新下载。旧文件保留在原路径作为恢复副本，不会自动清理；后续编辑只作用于新目录文件。删除应用内项目仍保留磁盘内容。文件移动记录恢复日志；跨磁盘移动暂不支持，失败时保持原文件和应用目录关系。
