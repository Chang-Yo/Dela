# 本地数据迁移

把旧版 Dela 留在本机的数据升级到当前格式。业务代码只认识当前格式，不含任何兼容旧数据的分支。

## 规则

1. **一次 schema 变更对应一个目录** `vNtovN+1/`，只处理相邻两个版本，并在 `index.ts` 的 `migrations` 里登记一行。跨多个版本时逐级串联执行。
2. **不 import 业务代码**。SQL、旧配置的结构与解析都写死在迁移目录里。业务代码以后会变，迁移代码不能跟着变。
3. **迁移代码一直保留，不删除。** 已发布的迁移不再修改，修复写成下一步。
4. **只迁移已有数据。** 新安装（无数据库或 `user_version = 0`）直接建当前 schema，不经过迁移。
5. **会动到的文件都要登记**到 `touchedFiles`。迁移前整份备份，任何一步失败都整体还原。SQLite 的改动在事务里；事务外的文件（如加密配置）先写临时文件再改名，并且可以重复执行。
6. **读不出的旧数据不猜测。** 保留原样，交给用户在应用里重新配置。
7. **每一步配一条测试**：用该版本的样本数据迁移，断言结果与失败时的还原。

## 新增一步

1. `database.ts`：改 schema，`SCHEMA_VERSION` 加一。
2. 新建 `vNtovN+1/index.ts`，在 `index.ts` 登记。
3. 在 `test/` 补测试。
