# Independent sealed confirmation corpus

This directory is owned by the independent confirmation author. It is frozen before the evaluated parser sees its cases. No production parser, old tests, old answers, old HTML, scores or new development corpus were read. Only a separately prepared source/article URL string blacklist was used for deduplication. No evaluated parser was executed during construction or annotation. `build.ts` constructs the authored cases and materializes independently reviewed public annotations; it imports only Node built-ins and the existing Cheerio HTML reader.

The contract is Issue 185: a user enters an arbitrary public URL, confirms a column, and later replays the extraction rule to identify newly added articles. Per-site production exceptions, arbitrary JavaScript execution, login, captcha solving and automatic pagination are outside scope. Tests evaluate static first-page structure at that boundary.

## Fixed scoring meaning

`mode: list` requires the entire expected article set, with no additional article from another column, navigation, footer, pagination or auxiliary link. Titles are compared after whitespace normalization only. The full `title` attribute on the same article anchor takes precedence over clipped visible anchor text. Anchor-local category prefixes are part of the title; a category label outside the anchor is not. Dates use only explicit page evidence. `YYYY-MM-DD` establishes that calendar day, a supplied timestamp establishes the full timestamp, and an unsupported or absent year remains `null`. Never infer a publication date from acquisition time, a footer, a URL or an unrelated row.

Every multi-column synthetic case carries `targetLabel` and a complete `sampleTitle`, so the requested list is explicit. Automatic preferred candidate, coverage of the user-confirmed candidate, and complete-title-assisted selection must be reported separately. The complete-title check requires the correct whole column, with zero contamination. It does not permit matching only the sample row.

Base rejection cases express unsupported boundaries. A safe rejection is counted as a boundary outcome, never a supported-list compatibility success. Transforms similarly distinguish exact correct replay from rejection. `replay: equal` requires the transformed expected list, falling back to the base expectation when `expected` is absent. `replay: reject-or-equal` permits safe rejection or exact expected replay and must report those outcomes separately. Extra or missing records cannot pass either mode. `new-identity` explicitly adds one unseen article and carries its whole transformed expectation; it checks new identities without relying on current publication order or a fixed count.

## Authored structure coverage

The authored set has 36 supported-list cases across 12 structural families and four unsupported cases. Each supported family has three coherent variants, with six through eight base records and three independent replay changes. Families cover definition pairs, article cards, date-first tables, whole-row anchors, split calendar display, unknown years/dates, complete title attributes, explicitly labelled competing columns, PDF notices, query identities, responsive copies and mixed explicit date formats. Changes add an inert sibling, add a new identity, or change presentation classes. Navigation and page-level maintenance dates are not article data. All synthetic domains use reserved example hosts.

## Public acquisition and manual review

Eight new public first pages are included. Every included raw response was obtained using existing `curl.exe`, normal TLS verification, redirects and a 25-second request limit, without credentials or executing site scripts. Raw bytes and response headers remain in `snapshots/`. The metadata retains requested and final URLs, acquisition time, HTTP result, byte length and SHA-256. The corpus HTML is a fatal-error-checked UTF-8 decoding of those exact bytes; it is not browser-rendered HTML or a reconstructed list.

The author read every included static list row, title anchor, href and date in tool output, checked first/last boundaries and exact counts, and reviewed title/date placement. `provenance/manual-annotations.json` preserves the explicit reviewed row selector, expected full set and each original row's serialized HTML as inspectable evidence. Cheerio was used as an independent HTML reader to materialize those manually fixed scopes, never as a call to the evaluated parser. All list rows from the audited first page are included. The pages provide 14, 14, 20, 10, 15, 54, 10 and 9 records respectively. No later page or linked article was visited for annotation; external or login-destination article URLs are preserved as links only.

The sources are Zhejiang University teaching demonstration centre, Fudan Graduate School, Peking University general affairs, Wuhan University, Peking University academic affairs, Peking University computing centre, Tsinghua University Library and Xi'an Jiaotong University academic affairs. These are cross-site controls. They do not estimate actual SJTU coverage. Institutions are not treated as independent CMS products: Sudy/WebPlus and Webber/VSB have direct asset markers; the PKU legacy layout is one shared template family with unknown CMS; Wiipu is a vendor-attributed template, not a verified CMS product. Thus the eight pages provide four observed template families and only two directly evidenced CMS products.

All candidate attempts remain in `provenance/acquisition.json`, including failures, duplicate-source exclusions and pages whose static DOM had no list rows. TLS verification failure was retained without `-k`; HTTP 404 was retained; raw HTML with script-only data was not executed or silently turned into article rows. These are acquisition or annotation limitations, not parser failures or compatibility successes. Additional successfully acquired but unselected material remains provenance only. Initial Node fetch probes failed because the tool's transport was unavailable; their diagnostic count is recorded separately from native curl page attempts.

The prior source URL blacklist was supplied by the coordinator as URL strings only. Both requested and final source URLs of every included page are checked against it after fragment/trailing-slash normalization. The blacklist SHA and count are recorded. Old titles, expected answers, HTML and score outputs are not consulted.

## Freeze and custody

`freeze.json` hashes the authored builder, corpus, answer projection, provenance, raw snapshots, headers and this specification. `sealed-summary.json` exposes counts and digests only. Neither file is a parser-performance report. The confirmation author does not disclose individual inputs or labels to the implementation agent before an explicit unblinding instruction. Corpus integrity must be checked before scoring; implementation changes prompted by unblinded failures require a new independent confirmation set for a fresh generalization claim.

The portable case shape is `{ id, family, mode, url, html, expected, sampleTitle?, notes?, transforms? }`, with optional metadata. `corpus.json` is an array. Expected entries are `{ title, url, publishedAt }`. Transform entries are `{ id, html, expected?, replay }`. The builder may be executed only for deliberate pre-evaluation rebuilding; it updates timestamps and the freeze. Ordinary verification must only read and hash sealed files, without rebuilding or calling the evaluated parser.
