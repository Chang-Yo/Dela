# 0024. 待办是用户安排的唯一入口，课表只显示学校课程

- 状态：已接受
- 日期：2026-11-21

## 背景

3.0 中待办和课表都能新建带时间的事项。待办可以「写入日历」，课表的月视图可以拖选日期新建事件，两边还互相显示，用户不知道新事项该放在哪里。自建事件存在交大课表模块的 `calendar_events` 表里，去掉交大模块后就看不到了。待办的数据又是按 Canvas 作业设计的：来源只有个人与 Canvas，条目带课程字段，外部来源只能登记一个。

## 决定

- 待办（`modules/todo`）是用户新建事项的唯一入口，兼做日程。每条待办可以没有时间，也可以有下面三种之一，三者互斥：
  - 截止：某个时刻前完成；
  - 时段：同一天内的开始与结束时刻；
  - 全天：一天或连续几天，按日期而不是时刻保存，结束日算在内。
- 只有截止类会逾期，时段与全天过去即结束。不支持重复事项。
- 待办只认三种状态：未完成、已完成、未知。来源自己的说法（例如「已批改」「需重交」）作为状态文字原样显示，待办不解读。
- 字段与 iCalendar（RFC 5545）一一对应：截止对应 VTODO 的 `DUE`，时段对应 VEVENT 的 `DTSTART`/`DTEND`，全天用 `VALUE=DATE`，只在转换时把结束日加一天。重复、提醒、优先级与参与人不建模。现在只保证能对应，导入、导出与订阅以后作为功能另定。
- 待办有列表与月历两个视图，在月历上点选或拖选日期新建。带时间的待办都显示在月历上，「写入日历」开关去掉。
- 外部来源经 `registerTaskSource` 登记，可以有多个，各自带名字。来源只提供自己知道的内容（标题、时间、状态、链接、正文与自己的编号），条目 id 由待办生成。条目按来源自定的分组归类（例如课程），逐组同步，一组失败不影响其他组；打开原页面的链接文字也由来源提供。这些条目只由同步改动。登不登记由来源模块自己决定。
- 课表（`sjtu/timetable`）只显示从学校同步的课程：只读，只有周视图，不往待办里登记，也不读待办。日历颜色与日期工具从待办移到 `ui`，课表不再依赖待办。
- 想同时看课程和个人安排时，由 Agent 分别读取课表与待办，界面不合并。

## 后果

- 迁移把 `calendar_events` 里的自建事件转为时段类待办，跨天的转为全天，原时刻与地点写进备注，然后删除这张表。原有个人待办都是截止类，「写入日历」标记丢弃。
- 待办里的 Canvas 状态与课程字段改为通用的状态、状态文字与分组，迁移按原状态换算。
- 课表的月视图、自建事件、与待办的互相显示，以及 Agent 命令 `create_event`、`delete_event` 一并移除，Agent 改用 `save_todo`。Canvas 专用的 `query_assignments`、`refresh_todos` 移到 Canvas 模块。
- 以后需要「计划某天做、某天交」时，可以给时段类加截止日期，不必推翻本决定。
