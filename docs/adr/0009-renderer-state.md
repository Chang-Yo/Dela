# 0009. renderer 状态按归属划分，Effect 只用于白名单场景

- 状态：已接受
- 日期：2026-11-10

## 背景

v2 的 renderer 有 228 个 Effect，其中约 130 个在弥补“状态没有归属”：用 Effect 取数，再用 requestId ref 丢弃过期响应，用定时器等待渲染。数据的真实来源在主进程，renderer 却各自维护副本，副本与来源不同步时只能再补一个 Effect。

## 决定

| 状态                 | 放在哪里                                              |
| -------------------- | ----------------------------------------------------- |
| 后端数据的请求与响应 | TanStack Query，取数函数是契约客户端（见 0011）       |
| 后端推送的数据流     | 每个领域一个 store，由 IPC bridge 统一订阅一次        |
| 导航                 | 唯一路由，用 action 取代“请求脉冲”                    |
| 偏好                 | 一个持久化的 store                                    |
| 组件本地状态         | `useState`；需要重置时用 `key` 或记下它所属的那批数据 |

- 全应用只有一个 `QueryClient`。数据都在本机主进程，默认不重试、切回窗口不重查。
- 输入防抖用 `use-debounce`，不在组件里写定时器。
- Effect 只用于订阅浏览器事件、外部连接、命令式第三方组件和外部定时器，规则写在 AGENTS.md。

## 后果

- 过期响应、并发请求和缓存由 Query 处理，组件里不再出现 requestId、`let active` 和定时器。
- 主进程推送变更时，需要让对应的查询失效；这条通路在第一个带推送的模块中建立。
- 新增两个依赖：`@tanstack/react-query` 与 `use-debounce`，均为 MIT。
