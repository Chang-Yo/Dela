# 0004. Agent 协议是唯一对外发布的契约

- 状态：部分取代（「协议从第一版起具备」由 [0015](0015-agent-protocol-v1.md) 取代）
- 日期：2026-11-09

## 背景

移动端（Flutter）将通过 IPv6 直连桌面端，只转发 Agent 对话。移动端和桌面端各自独立发布，版本必然不一致。v2 中约 45 个聊天 IPC 通道（`session:*`、`chat:*`、`sidechat:*`）把 Agent 交互和桌面私有功能混在一起。

## 决定

区分两种契约：

|        | 模块内部契约            | Agent 协议                               |
| ------ | ----------------------- | ---------------------------------------- |
| 位置   | 各模块的 `contract.ts`  | `core/protocol`                          |
| 使用方 | 同一模块的 main 和 view | 桌面 React 和移动端                      |
| 稳定性 | 可以随时修改            | 带版本号，向后兼容，由 CI 检查           |
| 格式   | zod                     | zod，并导出 JSON Schema 供 Dart 生成代码 |

Agent 协议包含会话、提问、取消、插队、切换模型、斜杠命令、后台任务、旁问、流式事件、附件和轮次变化。打开文件、Git 审阅、各项设置等属于桌面私有功能。

桌面 React 同样通过 Agent 协议访问 Agent，作为协议的第一个使用者。

协议从第一版起具备：

- 事件序号：重连后先取快照，再接收增量。
- 多客户端并发：明确谁可以取消、谁可以撤回。
- 不传本地路径：内容直接传输，或使用网关提供的地址。
- 版本握手：比对协议主版本，不一致时拒绝连接并提示升级；向后兼容的新增不升主版本。

## 后果

- 移动端不需要新的后端；测试可以直接通过协议驱动 Agent。
- 每个新功能都要先判断：它属于 Agent 交互，还是属于桌面便利功能。
- 修改协议需要做版本决策，这是长期成本。保持稳定的接口越少，其余部分的修改越便宜。
- 网关对公网可见，安全要求另行记录。
