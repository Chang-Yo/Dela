# 0005. 交大代码是叶子模块，暂不建校园兼容层

- 状态：已接受
- 日期：2026-11-09

## 背景

长期设想是让其他高校定制自己的 Dela。但目前只有交大一个样本，从一个样本提炼出的“通用抽象”，很可能只是换了名字的交大做法。另一方面，v2 中通用代码直接引用交大代码（例如 `todo` 引用 `canvas`，`notifications` 引用五个来源），导致交大代码无法整体拿掉。

## 决定

- 不建校园兼容层。交大功能集中放在 `sjtu/`。
- 判断标准：如果交大不存在，这个功能还有意义吗？有意义放进 `modules/`，没有意义放进 `sjtu/`。例如邮件放 `modules/mail`，交大邮箱只是一条预设数据；课表和 Canvas 放 `sjtu/`。
- 依赖只能从 `sjtu` 指向外部。通用模块需要交大数据时，由通用模块在自己的 `index.ts` 中定义注册口（例如 `TaskSource`、`NoticeSource`），交大模块把数据注册进去。通用模块之间也用同样的方式协作。
- 模块间通信优先直接调用 `index.ts`；一个使用方、多个提供方时用注册口；事件只在有多个监听方时使用。

## 后果

- 在 `app/modules.ts` 中去掉所有交大模块后，应用仍能构建和运行。CI 用这个构建验证依赖方向。
- 需要维护约 8 处注册口，其中 3 处（命令与 Skill、资源解析、会话作用域）是 Core 边界本来就需要的。
- 出现第二所学校时，把 `sjtu/` 挪到 `schools/sjtu/`，再从两份真实实现中提炼共性。
