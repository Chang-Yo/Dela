# 0021. 通用会话经辅助目录看到资料

- 状态：已接受
- 日期：2026-11-15

## 背景

通用会话（不属于项目的会话）有两种工作目录：首页随聊用每个会话私有的 `chat-sessions/<id>`，资料页新建的会话用 canvas 登记的会话作用域 `library`，也就是课件下载目录。结果资料页的对话由 Canvas 决定：Agent 看不到用户放在资料里的文件，没有 Canvas 的构建里还会退回私有目录。协议的 `chatScopeSchema` 因此带着一个交大概念。@ 引用的候选只按工作目录过滤，随聊里同样看不到资料。

## 决定

- **工作目录不变**：通用会话一律用私有目录，新文件默认写在这里。资料页与首页新建的会话没有区别，只是标签打开的位置不同。
- **辅助目录**：core 提供 `registerContextDirectory({ id, label, directory })`，取代 `registerSessionScope`。workspace 模块登记资料根目录 `workspace/`，canvas 登记课件目录。通用会话的系统提示列出这些目录及其名称，Agent 需要时自己检索。辅助目录与工作目录一样可读可写，不加约束。项目会话不带辅助目录。
- **@ 引用**：通用会话的候选是私有目录、资料根目录与模块登记的候选（如已下载的课件）的并集。资料里的项目子树不进候选，避免代码仓库淹没列表。
- **协议**：通用会话只剩一种，`create-session` 去掉 `scope` 字段，删除 `chatScopeSchema`。移动端尚未发布，协议在 v1 内修改，不升版本；多传的 `scope` 会被 schema 忽略。

## 后果

- 已有会话的工作目录写在数据库里，照常可用，不迁移。它们同样获得辅助目录。
- 首页与资料页的空会话不再按作用域区分，新建时互相复用。
- 去掉 canvas 只少一个辅助目录与它的 @ 候选，资料页的对话照常工作。
- 以后的来源（课堂文稿、水源收藏）按同样方式登记目录，不加新入口。
