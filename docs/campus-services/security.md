# 安全、隐私与合规

[← Wiki 首页](README.md) · [服务目录](README.md#服务地图) · [资料索引](sources.md) · [待核查服务](roadmap.md)

本页集中记录各服务共用的安全边界。开发者应在实现前重新核对服务方当前页面。

> [!IMPORTANT]
> 先确认凭证存放、最小权限、数据去向、写操作确认和撤销路径，再开始接入服务。

## 凭证与会话

- App Secret、Access Token、邮箱密码、User API Key、API Key、Cookie 和 SSH 私钥都按密码级凭证处理。
- 凭证只保存在服务端 Secret Store、操作系统钥匙串或等效的加密存储中。
- 不把凭证放入 URL、前端源码、公开仓库、错误报告、分析系统或日志。
- 浏览器会话只交给对应校园域名使用；不要把 Cookie 发送给模型或第三方扩展。
- 临时媒体地址和下载签名本身也可能直接授予访问，应按短期凭证处理。
- 用户断开服务时，应同时删除本地凭证；服务支持撤销时，应先完成服务端撤销。

## 最小权限与个人数据

- 只申请当前功能需要的 scope、字段和写入能力。
- 默认将邮件正文、私信、成绩、校园卡流水、流程表单和课堂内容视为私密数据。
- 数据只进入用户主动发起的任务；不要默认进入长期记忆、公开索引或共享数据集。
- 写操作应展示目标、内容和影响，并让用户在执行前确认。
- 增量同步失败时保留已有缓存并显示错误，不把空响应直接当作数据已删除。

## 平台规则

- jAccount 和 Open API 应使用应用获批的 App ID、回调地址和 scope。
- 校级数据资源只能用于申请时声明的用途和获批字段；官方规则禁止将数据直接或变形后提供给第三方。
- InfoPlus User Token 代表用户，System Token 代表应用；两者不能互相替代。
- Canvas 个人 Token 适合本人使用。需要由应用统一承载多位用户授权时，应联系 Canvas 管理方申请 Developer Key，并使用 OAuth。
- 水源服务协议要求非官方客户端、脚本以及 API 或 RSS 间接访问事先取得书面许可。User API Key 授权仍应建立在该许可之上。
- 水源网页端当前没有完整的 User API Key 管理入口。客户端应保存 Client ID，并提供调用 /user-api-key/revoke 的撤销流程。
- 课堂视频的机器转写和 OCR 是辅助数据，需要保留原录像作为核对来源。第三方播放器中的播放不应被描述为官方观看考核记录。
- Pan 和网络短信目前没有在本指南中验证公开第三方自动化接口。域名与网站服务按官方表单、后台和邮件流程办理；jCloud 自动化应使用官方 API 中心公开的项目 Token 和 REST API。
- Skill 集市中的校园共建和社区项目各自维护；收录不等于学校对代码、权限或数据处理方式作出保证。

## 内容与模型

- 把课程资料、邮件、论坛内容或流程数据发送给模型前，应明确展示将发送的内容和模型服务。
- 只发送完成当前任务所需的最少数据。
- 不把他人帖子、邮件、课堂录像或附件重新公开分发。
- 自动摘要、ASR 和 OCR 可能出错，应标注来源并提供回到原文或原视频的链接。
