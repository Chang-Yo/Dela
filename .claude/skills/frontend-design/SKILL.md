# Frontend Design

按下面的流程开发前端页面，全程遵守「硬规则」。细节按需读取 `references/`，不要一次性全部加载。

## 流程

1. **定类型**：明确页面类型（后台 / 产品展示 / 业务咨询 / 博客等）、展示目的和目标人群。→ `references/page-type.md`
2. **定系统**：写任何样式之前，先确定设计系统（字号、间距、颜色、圆角），并放在单独的文件中。已有设计系统的项目直接沿用，有代码但无规范的项目先提取。→ `references/system.md`
3. **搭框架**：设计页面整体框架与布局，明确每个部分所属的容器，为各级容器选好 display 方式（flex / grid / block）。内容用空白或占位符，不要过早聚焦具体内容。
4. **填内容**：mock 内容，填充细节，获得对样式的基本反馈。文案与交互遵循 → `references/ux-copy.md`
5. **查响应式**：→ `references/responses.md`
6. **加动画、调过渡**：布局和样式定稿后再加动画。→ `references/motion.md`
   - 不同页面的主题风格是否连续、是否出现突兀的颜色或对比度变化（刻意为之的除外）
   - 同页面各 section 的过渡是否自然，视线引导的顺序是否合理

交付前对照「交付前检查」，遇到问题时查阅 `references/pitfalls.md`。

## 硬规则

**一致性**

1. 全局样式统一是第一优先级。padding、margin、radius、字体、字号、字重、对齐、方向、颜色、transition、animation 都必须来自预定义的 token，不得出现 token 之外的魔法数值。
2. 字号、间距、颜色必须从预定义的阶梯中选取。多个色相时，每个色相各自定义阶梯；有明暗两种主题时，两种主题各自定义。
3. 没有指定主题色系时，默认只使用灰度。文字与背景禁止使用同一色相。配色整套选用，不混搭。

**层级**

4. 先明确页面各部分的地位，再强调该强调的、弱化该弱化的。每个视图只有一个视觉焦点。
5. 弱化次要信息靠对比度、字重、间距，不靠边框和分割线。谨慎使用实线，优先用排版解决分区问题。

**响应式**

6. 默认必须做响应式：窄屏（< 768px）、中屏（768–1024px）、宽屏（> 1024px）、超宽屏（如 24 寸显示器）。重点检查溢出、重叠、挤压，以及 margin / padding / gap 是否合适。

**文案**

7. 不把用户意图、模块设计目标、开发者意图写在屏幕上。文案简洁、直白、无歧义，学习 Apple 的文案风格。
8. 标题要能统领描述。按钮本身已能表达动作时，删掉冗余的功能描述。
9. ICON 与文字的取舍顺序：语义明显的纯 ICON ＞ ICON + 悬浮提示 ＞ ICON + 文字标签。默认用户有基础的界面认知。

**交互**

10. 危险操作必须二次确认，按严重程度分两档：
    - 常规敏感（如归档旧聊天记录）：在原按钮位置直接显示确认步骤，保证高频操作的效率
    - 不可恢复（如彻底删除数据、重置所有设置）：弹出专门的确认框，让用户聚焦于这个动作

**动画**

11. 动画必须风格统一。出现方向要与页面布局一致，并考虑它对用户视线的影响。
12. 不需要变化的部分保持稳定，排查并消除所有未明确指定的界面抖动。

## 优先级

冲突时按以下顺序裁决：

1. 项目已有的设计系统与代码风格
2. `references/page-type.md` 中该页面类型的风格要求
3. 本文的通用规则

「弱化分割线」「默认灰度」「动画克制」属于默认值。页面类型明确要求时以后者为准，例如业务咨询页用线条划分板块，产品展示页用高饱和配色和灵动动画，后台系统保守甚至无动画。

## 交付前检查

- [ ] 所有样式值都来自预定义 token，没有魔法数值
- [ ] 页面有清晰的视觉焦点，次要信息已被弱化
- [ ] 四档屏宽下都已检查，无溢出、重叠、挤压
- [ ] 屏幕上没有解释设计意图的文字，没有冗余文案
- [ ] 危险操作都有二次确认，且档位正确
- [ ] 动画风格统一，没有无意的抖动
- [ ] 已对照 `references/pitfalls.md` 中的相关条目

**可用性对照（Nielsen 十条的落地写法）**

- 系统状态可见：异步操作都有加载、成功、失败的反馈
- 用户控制与自由：能撤销、能退出；危险操作有二次确认
- 一致与标准：同类元素同一种写法
- 识别而非回忆：用 ICON + 悬浮提示，让选项可见，不要求用户记忆
- 极简设计：无关信息一律删除
- 错误恢复：错误信息用人话，指出问题并给出下一步
