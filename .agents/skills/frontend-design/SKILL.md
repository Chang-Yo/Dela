# Frontend Design Priciples

请在前端开发中遵循以下原则。

## Core Principles

- 全局样式统一是最重要的，这包括
  - padding, margin, radius
  - fontfamily, fontsize, fontweight
  - align, direction
  - color, trasition, animation
- Hierarchy is EVERYTHING
  - 明确页面各个部分的地位，再对应的页面强调需要强调的，淡化需要淡化的
  - 通过适当淡化其他部分来强调需要强调的部分
- 必须遵循一套设计系统，无论是专门配置代码文件，还是代码风格默认遵守
  - 字体需要预先定义好一系列字号，所有的字体都需要从中选择
  - 颜色需要预先定义好一系列梯度，如果有多个色相，每个色相都需要分别定义；如果有黑白两种主题，两种主题都需要分别定义
  - 间距需要预先定义好一系列间距值，所有的 margin, padding, gap都从中选取
- 默认情况下，必须考虑响应式设计
  - 至少考虑窄屏（< 768px），中屏（768px – 1024px），宽屏（> 1024px）三种情况下的显示
  - 重点观察是否出现溢出的情况
  - 重点观察是否出现margin, padding或gap不合适的情况
- 文案必须保持简洁，精准
  - 不要把用户的意图、模块的设计目标写在屏幕上
  - 去掉状语
- 动画重要，但不能过早添加。
  - 再尚未确定最终的布局和样式时，使用简单的动画（如淡入淡出）或者干脆不适用动画
  - 动画必须有统一的风格

## 步骤

1. 清楚定义该前端页面是什么类型，前端展示的目的是什么，面向的目标人群：是给员工用的后台，是自己的博客还是一个产品的介绍页面，或者其他。
   可以参考 `references/page-type.md` 来获取基本的背景要求。

2. 事先预设好前端开发的一套system，具体可以参考 `references/system.md`

3. 根据用户的意见，先设计好页面的整体框架（framework）和组件布局（Layout），区分清楚每个部分所属的容器，为各种层级的容器选择好的display方式（flex, grid, block等等）。
   初始时内容可以用空白或占位符设计，**不要过早的聚焦于具体内容**

4. 完成主题框架的设计后，通过 mock 一些内容，填充细节，获得对样式的基本反馈

5. 检查前端的响应式设计，具体可以参考 `references/responses.md`

6. 优化过渡的场景
   - 不同页面的主题风格是否连续，遵循同一套设计思想。切换时是否会出现十分突兀的变化，比如颜色，对比度。
     - 如果有，尝试检查两个页面是否遵顼同一套设计系统
     - 如果是刻意为之，可以忽略
   - 同一页面不同section之间的过渡是否自然，**重点关注用户视线的引导**顺序是否合理
