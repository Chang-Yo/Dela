# 踩坑记录

交付前对照相关条目。每条格式：症状 / 根因 / 做法 / 检查。
同类问题出现 2 次以上，提升为 SKILL.md 的硬规则；确认不再相关的条目直接删除。

## 主题与颜色

### 背景图换了，调色板和遮罩没跟着重审

- 症状：换背景图之后，正文在图的亮部或暗部读不清，强调色与画面冲突
- 根因：调色板和遮罩浓度是针对旧图定的，背景图才是设计的锚点
- 做法：先定背景图，再从图中取色确定调色板、遮罩和文字色；换图等于重审整套
- 检查：在图中最亮和最暗的位置各看一次正文，对比度不低于 4.5:1；窄屏裁切导致背景位置变化后再看一次
- 来源：博客重设计，冷调雨窗图与暖调 Vesper 配色未对齐

### 多主题时，组件直接引用色名 token

- 症状：切换主题后，部分组件颜色不变，或对比度崩坏
- 根因：组件写的是 `--color-dusk-taupe` 这类色名，主题只替换了其中一部分变量
- 做法：组件只引用语义 token（`--text`、`--text-muted`、`--surface`、`--accent`、`--divider`），每套主题负责把语义 token 映射到具体色值。`assets/palettes/` 里的色名 token 只作为取色来源，项目中要再映射一层
- 检查：逐个主题切换后把每个页面过一遍；全局搜索组件样式，不应出现色值或色名 token
- 来源：博客重设计，计划提供读者可选的多套主题，每套配一张背景图

## 交互与动画

### 悬停放大文字，周围元素被一起推动

- 症状：导航项放大时，相邻项、容器宽度或其他区域跟着抖动
- 根因：用 `font-size` 放大会触发重排，影响所有相关元素的盒模型
- 做法：放大用 `transform: scale()`，`transform-origin` 固定在对齐边。设计本就要求「挤开」邻居（如分割线下移）时，只让指定元素位移，并给容器预留空间
- 检查：在多个导航项之间快速滑动，容器边界不变，只有指定元素在动
- 来源：博客重设计，左侧导航悬停时文字放大、分割线下移

### 只在 hover 时出现的信息，触屏上看不到

- 症状：在手机和平板上，图标的文字标签永远不出现，或 hover 状态粘住不消失
- 根因：触屏没有真正的 hover
- 做法：hover 效果包进 `@media (hover: hover) and (pointer: fine)`。关键信息不能只靠 hover 传达：图标语义要明确，并加 `aria-label`
- 检查：用开发者工具切换到触屏设备模拟，逐个核对只在 hover 时可见的信息
- 来源：博客重设计，右侧联系图标靠 hover 展开标签，移动端与 iPad 方案待定

### 多页切换时背景闪烁或重置

- 症状：点击导航后，背景图重新加载、闪白，或位置跳回起点
- 根因：每个页面各自挂载背景，整页刷新时被重建
- 做法：让背景处于跨页面常驻的层（或用 View Transitions、局部替换内容），切换时只动前景和模糊度；背景图预加载，并设置 `background-color` 兜底
- 检查：连续切换 3 个以上页面，背景不闪、不重新加载（网络面板确认缓存命中）
- 来源：博客重设计，背景始终存在，转场像焦点移动而不是换页

## 字体与资源

### 中文字体体积大，首屏加载慢或与西文风格割裂

- 症状：首屏中文先显示系统字体再跳变，或中英混排时风格、字重不协调
- 根因：整包 CJK 字体体积大；字体栈没有显式写出 CJK 回退
- 做法：woff2 加 `unicode-range` 子集，`font-display: swap`，首屏用到的字体预加载；字体栈中西文和中文各自写全回退
- 检查：限速网络下刷新首屏；检查中英混排段落的字重与行高
- 来源：博客重设计，Cormorant Garamond 搭配霞鹜文楷，自托管 woff2 子集

### 依赖境外 CDN 的字体、图标、脚本

- 症状：页面在国内加载很慢，或字体、图标缺失
- 根因：运行时依赖了境外 CDN
- 做法：字体、图标 SVG、脚本都自托管；部署平台也要考虑国内的可访问性
- 检查：在构建产物中搜索外部域名；网络面板确认第三方请求为 0
- 来源：博客重设计，部署从 GitHub Pages 迁到 Cloudflare Pages，字体与图标自托管

### 设置中的字号选项只对工作区无效

Dela开发时发现字号选项对聊天区的字体显示无效，检查发现聊天区的前端设计没有遵循整个系统的 design token,导致出现了孤立的现象。
最终修复方式是统一为相同的设计系统。

## 没有及时支持暗色模式

- 案例：改了某处组件的颜色，或者为某个组件新换了主题，但是没有考虑到对暗色模式的支持（假如有）
- 检查：首先根据设计系统检查是否需要双主题，如果有，每次写组件都要认真适配

## 折叠侧边导航栏

### 在折叠或展开时出现少量几帧字体被挤压的现象

比如“ICON+Label"形式的折叠侧边栏，一种容易出现视觉缺陷的做法是：利用Label显示宽度的减少来完成折叠。

但是由于折叠时宽度减少，文字并没有小时，于是就会被挤压换行，导致出现几帧文字竖直排列的情况

- 解决方法：改为全部折叠；如果折叠后依然保留ICON,可以将ICON和Label分为两部分分别对待，这样折叠时可以利用不透明度和层级覆盖直接处理Label,ICON的视觉位置也很稳定

## 报错

### 报错信息不走定义好的 toast notification组件

已经定义好toast notification，但是很多部分的报错显示依然没有走这条路，而是直接将红色报错文本显示在屏幕中，甚至导致布局重排。

- 解决：报错尽量走系统通道，不要直接显示在屏幕上
