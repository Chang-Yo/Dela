# 动画

**动画重要，但不能过早添加。**
动画要服务于用户的视线和意图，不是装饰。

## 何时加

- 布局和样式尚未定稿时，只用简单的淡入淡出，或者干脆不用动画。
- 定稿之后，再统一设计动画。

## 统一风格

- 在设计系统里预定义动画 token（见 `system.md`），所有动画从中选取：时长和缓动曲线（一到两条）。
- 同类元素用同样的动画，同样的交互用同样的时长和缓动。
- 优先只对 `opacity` 和 `transform` 做动画，避免对 `width`、`height`、`top`、`left` 做动画，以免引起重排和卡顿。
- 尊重 `prefers-reduced-motion`，用户开启减少动态效果时，关闭或简化动画。

## 视线引导

动画的出现方向必须与页面布局相关，并始终考虑它对用户视线的影响。

- 用户习惯从上往下阅读，窄屏上尤其如此，内容的进入方向要顺着这个习惯。
- 菜单、面板从触发它的位置展开，不要凭空出现：
  - 触发入口在右上角：面板从上往下，或从右往左展开
  - 触发入口在左上角：面板从左往右展开
  - 触发入口在底部：面板从下往上展开
- 元素退出时，走与进入相反的路径。
- 一次只引导一个焦点，同一时刻不要有多处元素争夺注意力。

## 保持稳定

不需要变化的部分，界面必须保持稳定。排查并消除所有没有明确指定的抖动：

- 图片、卡片、骨架屏提前预留尺寸，避免加载后内容被顶开
- 悬停、选中状态不改变元素的盒模型尺寸（用 outline、shadow 或 transform 代替改边框宽度）
- 弹层出现时防止页面滚动条消失造成的横向跳动
- 文字内容切换时，容器宽高不要突变

## 按页面类型选择力度

| 页面类型 | 动画力度                                               |
| -------- | ------------------------------------------------------ |
| 后台系统 | 保守，甚至无动画                                       |
| 产品展示 | 灵动，可以有进场和滚动动画，用渐变与模糊让交界自然过渡 |
| 业务咨询 | 不花哨，稳重，以淡入、轻微位移为主                     |
| 博客     | 克制，以阅读为先                                       |

## 检查

- [ ] 动画时长和缓动都来自预定义 token
- [ ] 同类元素的动画一致
- [ ] 进入方向与布局、触发位置一致
- [ ] 悬停、加载、切换时没有意外的位移或抖动
- [ ] 开启「减少动态效果」后页面仍然可用
